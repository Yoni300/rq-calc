# Публічні білди: підключення сервера (Supabase)

Займає 5–10 хвилин, один раз. Supabase безкоштовний для такого обсягу.

## 1. Створити проєкт

1. Відкрий [supabase.com](https://supabase.com) → **Start your project** → увійди через GitHub.
2. **New project**:
   - Name: `rq-calc`
   - Database Password: будь-який надійний (збережи собі, програмі він не потрібен)
   - Region: **Central EU (Frankfurt)** — найближчий
3. Натисни **Create new project** і зачекай 1–2 хвилини.

## 2. Створити таблицю білдів

1. Ліворуч **SQL Editor** → **New query**.
2. Скопіюй увесь вміст файлу `server/supabase.sql` і встав.
3. Натисни **Run**. Має з'явитися «Success. No rows returned».

## 3. Скопіювати адресу та ключ

1. **Project Settings** (шестерня) → **API Keys** (або **Data API**).
2. Скопіюй:
   - **Project URL** — виглядає як `https://abcdefgh.supabase.co`
   - **Publishable key** (`sb_publishable_…`) або **anon public** key (`eyJ…`)

⚠️ Не копіюй `service_role` / `secret` ключ — він дає повний доступ до бази.

## 4. Вписати в програму

Відкрий `app/config.js` і встав:

```js
window.RQC_CONFIG = {
  supabaseUrl: 'https://abcdefgh.supabase.co',
  supabaseKey: 'sb_publishable_...',
};
```

Перезапусти калькулятор → вкладка **Білди**.

## Що можуть гравці

- Дивитись усі публічні білди, фільтрувати за класом, сортувати (нові / популярні), шукати.
- Публікувати свій білд (назва, нік, опис).
- Ставити лайк: один на білд з однієї IP-адреси. Сервер сам пам'ятає, хто що лайкнув, і забрати лайк може лише той, хто його поставив.
- Публікувати не більше 10 білдів на добу з однієї адреси.
- Видаляти **лише свої** білди: при публікації програма зберігає на комп'ютері секретний токен, а на сервер іде тільки його хеш.

Публічний ключ у програмі — це нормально: він дозволяє лише те, що прописано в `supabase.sql` (читати, публікувати, лайкати, видаляти своє).

## Оновлення бази

Після `supabase.sql` по черзі виконай у SQL Editor:

1. `002-unlike.sql`: можна забрати свій лайк.
2. `003-fair-likes.sql`: чесні лайки (сервер пам'ятає, хто лайкав) і ліміт публікацій. IP-адреси не зберігаються, лише їхній хеш із секретною «сіллю».
3. `004-build-tags.sql`: теги на збірках (до 5 з фіксованого списку, сервер перевіряє список).
4. `005-edit-tags.sql`: автор може змінити теги вже опублікованої збірки.
